# 场地有约 · 校园场地预约

操场 / 体育馆的多日期预约日历。中文界面，双周与月视图，上午、下午 / 晚间分栏，精确到分钟预约，支持体育课表导入。

**本次交付阶段：GitHub Pages 公开预览。没有部署 Netlify。真实账号与共享写入暂未启用。**

- [公开预览](https://petershe1by.github.io/campus-venues/)
- [完整流程演示](https://petershe1by.github.io/campus-venues/?demo=1)

## 当前如何体验

打开完整流程演示，点击“账号登录”，选择“演示管理员”或“演示申请人”。演示数据只保存在当前浏览器；演示角色无需密码，不构成真实身份认证。可在“预约须知”重置演示数据。

公开页面默认使用 `public/schedule.json` 的空日历，没有把示例活动冒充真实预约。真实体育部课表尚未提供。需要在 GitHub 预览公开真实占用时，可由仓库管理员整理并更新该文件；只应放日期、场地、活动名称、时间和公开组织信息，不放填写人或账号信息。

## 权限与记录

| 身份 | 正式后端启用后的权限 |
| --- | --- |
| 游客 | 查看占用日历、筛选场地、搜索活动和课程；不获取填写人的姓名或账号 |
| 申请账号 | 使用大管理员分发的账号登录，首次修改密码，填写预约，查看/取消自己的活动预约 |
| 唯一大管理员 | 创建/停用申请账号、重置初始密码、导入/替换课表、查看全部填写人、取消预约、查看操作日志 |

没有公开注册，没有创建第二个大管理员的接口。正式密码使用独立随机盐和 scrypt 哈希。会话是 HttpOnly、Secure、SameSite=Strict Cookie，服务端只保存会话令牌摘要；停用/重置账号会撤销该账号的现有会话。

申请人无法指定填写人。每次预约由服务端从登录会话记录使用人 ID、姓名快照、登录账号快照、创建时间。取消保留原记录与取消人。日志记录账号创建、停用、密码重置、课表导入、预约创建和取消。

## 预约规则

- 北京时间（Asia/Shanghai）；选择任意日期及 00:00–23:59 内的分钟时间。已过去的时间不可新约。
- 操场整场和体育馆整馆作为两个独立资源；尚未虚构篮球场等实际分区。
- 同一天同一场地，区间有重叠即拒绝；前一场结束时间可等于后一场开始时间。
- 上午为 00:00–12:00，下午 / 晚间为 12:00–24:00。跨中午活动在两栏显示。
- 跨天活动分开申请；目前每条记录必须在同一天内，结束时间最晚 23:59。
- 正式后端以数据库事务确认，无冲突自动通过。前端预检查仅用于提示。
- 体育课程也参与占用检查。导入存在冲突时整批拒绝；不会自动挤掉已经确认的活动。

## 体育部课表导入

管理员进入“课表导入”，下载 CSV 模板，选择 UTF-8 CSV 或 XLSX（最大 5 MB，仅第一个工作表）。支持 Excel 的日期、时间小数、时间单元格、公式缓存结果。旧 `.xls` 请先另存为 `.xlsx`。

一行一节课，列名如下：

| 日期 | 场地 | 开始时间 | 结束时间 | 课程名称 | 周次 | 星期 |
| --- | --- | --- | --- | --- | --- | --- |
| 2026-10-26 | 操场 | 08:00 | 09:35 | 大学体育 | | |
| 留空 | 体育馆 | 14:00 | 15:35 | 羽毛球课 | 1-16(单) | 2 |

有“日期”时按具体日期导入；无日期时设置第 1 周星期一，按“周次＋星期”展开。星期 1–7 表示周一到周日。支持 `1-16`、`1,3,5`、`1-16(单)`、`2-16(双)`，最多 30 周、2000 条展开记录。场地仅接受“操场”“体育馆”（或内部 ID `field` / `gym`）。

导入前显示源文件行号、展开日期、错误和冲突。追加模式跳过完全相同的课程；替换模式保留旧课取消记录并保留活动预约。合并单元格、课程节次编号、图片/PDF 课表无法凭空确定实际起止时间，需要先根据学校作息整理，或提供原始文件后做专门适配。

## 本地运行

Node.js 22.13+：

```powershell
npm ci
npm run dev
```

前端预览启动后进入打印的本地地址，使用“体验完整流程”。

完整账号后端也可在本机运行，数据保存在 Git 忽略的 `.local-data/database`（PGlite PostgreSQL）：

```powershell
$env:ADMIN_USERNAME='admin'
$env:ADMIN_INITIAL_PASSWORD='换成至少12位的随机初始密码'
npm run dev:full
```

然后打开 `http://127.0.0.1:5173/`，使用上述账号登录，立即修改密码。若端口占用，先停止冲突的服务；API 本地端口为 8788。仅绑定本机，HTTP 开发 Cookie 不带 Secure；正式 Netlify Cookie 强制 Secure。

```powershell
npm test
npm run build
```

## GitHub Pages

仓库 Settings → Pages → Source 设置为 **GitHub Actions**。`.github/workflows/pages.yml` 在 main 推送后执行测试、构建并部署，前端资源使用相对路径，适配 `/campus-venues/` 子目录。GitHub 构建明确关闭真实 API，账号服务显示“尚未启用”。

## 以后再启用 Netlify（本次未执行）

1. 从此仓库创建 Netlify 项目；已有 `netlify.toml`（`npm run build`，发布 `dist`，函数在 `netlify/functions`）。
2. 提供 PostgreSQL 数据库，可使用 Netlify DB 或兼容 PostgreSQL 服务。把连接字符串保存为服务端环境变量 `DATABASE_URL`，不要放到 GitHub、前端变量或代码中。
3. 服务端环境变量设置 `ADMIN_USERNAME` 和至少 12 位的 `ADMIN_INITIAL_PASSWORD`。第一次正确登录才初始化唯一大管理员，并要求改密。完成后移除初始密码变量，后续使用数据库保存的密码哈希。
4. Netlify 构建环境下自动开启 `/api/*`；部署后测试游客日历、管理员初始化、账号分发、申请和课表导入。当前只完成本地/API 测试，尚未做 Netlify 云端验证。
5. 在正式发布前按校内要求确认公开展示的活动名称和组织信息。填写人的姓名、账号、密码哈希、日志始终通过权限接口访问，不导出到静态目录。

后端数据库使用专用 `campus_venues_state` 表。所有读写通过事务及 `SELECT ... FOR UPDATE` 串行化，避免同时申请导致重叠，也保证课表批量导入的原子性。适合小规模校内使用；大规模账号、预约和长期日志需迁移为独立关系表及归档策略。

数据库自动建表，数据库用户需有建表及读写权限。备份数据库即可保留账号、预约、取消历史和日志。不要清空此表来“重新初始化管理员”。公开 GitHub 仓库不包含数据库、真实账号、密码或会话密钥。
